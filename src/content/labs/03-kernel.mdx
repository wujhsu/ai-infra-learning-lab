需要 CUDA <Term id="gpu" label="GPU" /> 与 PyTorch 2.14.0。选择与驱动兼容的官方 wheel，记录实际 CUDA/<Term id="nccl" label="NCCL" /> 版本。实验脚本在无 GPU 时明确失败，不生成替代性能数据。

## 先跑正确性，再计时

```bash
python3 labs/kernel/benchmark.py > kernel-results.json
```

脚本对相同输入检查 eager 与 compiled 结果，再分别热身，使用 CUDA events 记录 30 组样本，每组重复 100 次。JSON 保留中位数与全部样本，而不是只给最快值。

先预测融合是否减少 launch 和中间写回，再观察 profiler。若输入很小，固定开销可能占主导；改成不同 shape 后，编译和资源占用也会变化。每次修改建立独立结果文件。

## 观察优化器的另一种融合

```bash
python3 labs/kernel/optimizers.py > optimizer-results.json
```

single、foreach 和 fused 使用相同种子创建新的参数与状态，避免前一组训练影响后一组。记录平均 step 时间、峰值分配与损失样本。这个二次函数优化只是路径对照，不等于真实模型收敛评估。

## 边界测试

增加非整块尺寸、较小张量和不同 <Term id="dtype" label="dtype" />。先检查结果，再接受性能。不要为了让测试通过任意放宽容差。把编译首次调用和稳定运行分开，记录是否发生重新编译。

## 验收与清理

提交脚本配置、环境、原始样本、正确性结果及一次无收益或失败的尝试。脚本退出后释放 GPU 进程；确认没有遗留进程占用设备。设备端实验在作者环境未运行，网站不展示虚构提升数字。
