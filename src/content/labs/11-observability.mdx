需要运行中的 vLLM 服务。基础指标采集使用 Prometheus 3.5.0，固定版本用于实验；请求级 trace 使用下方 OTel / Jaeger 配置，GPU collector 按实际平台接入，不伪造不存在的 span。

## 启动最小采集器

```bash
cd labs/observability
docker compose up -d
```

访问本机 `http://127.0.0.1:9090`，在 Targets 检查 `vllm-lab`。模型启动脚本会创建共享网络 `ai-infra-lab`，采集器通过该网络上的 `inference-lab:8000` 访问服务。实验脚本中的容器名需要保持一致；服务在另一机器时修改为实际可达地址并记录。

## 从真实指标建立查询

先访问服务 `/metrics`，读取 HELP/TYPE。Counter 看窗口增量/速率，Gauge 看当前值，Histogram 先确认桶与单位。不要从旧文章复制字段后把空图解释成零。

运行实验 04 三组负载，保存请求 JSONL、Prometheus 查询与时间窗。记录队列、输入输出、KV 使用和抢占，判断变化是否支持你的假设。

## 加入追踪与设备关联

实验包锁定 Collector Contrib 0.160.0 和 Jaeger 2.20.0，提供独立 trace 配置。它使用内存存储，停止前导出调查证据。

```bash
# 在项目根目录启动追踪后端
docker network inspect ai-infra-lab >/dev/null 2>&1 || docker network create ai-infra-lab
docker compose -f labs/observability/tracing.compose.yaml up -d
# 若实验 01 的服务仍在运行，先停止该实验实例，再按原模型 revision 重启
TRACE_ENDPOINT=grpc://collector:4317 bash labs/serving/serve.sh
```

第二条命令前台运行模型服务；另一个终端发送携带 traceparent 的请求：

```bash
python3 labs/observability/trace_request.py > trace-request-result.json
```

打开 `http://127.0.0.1:16686`，选择 `vllm-lab`，核对文件中的 trace_id 与服务实际输出的 span。这个标准库客户端只传递上下文，不导出自己的父 span；UI 中缺失客户端节点是明确边界，不应手工补成测量证据。若引擎没有继续使用该 trace_id，检查其版本、导出配置和上下文提取，而不是先认定链路已连通。

vLLM 0.29.0 的官方 OTel 示例说明核心依赖已随包提供；不要照搬旧文章重复安装不匹配的依赖。引擎与 Collector 使用共享 Docker 网络，通过 collector:4317 连接；跨主机时需要改成实际可达 collector 地址。当前配置只用于本地实验的明文传输。

验证真实请求 context 传播，记录 <Term id="pod" label="Pod" /> UID、节点与 GPU UUID 映射。若引擎没有某一阶段 span，就保留缺失，不手工补成仿真证据。

GPU 指标采集需要对应平台 exporter 与权限。验证抓取间隔、时间同步和设备标识，再将同窗口数据与请求阶段关联。共享 GPU 的指标不作精确单请求归因。

## 验收与停止

完成长输入、并发增加和 KV 压力三份调查记录，每份包括假设、证据、反证与动作。保存 dashboard/查询导出、原始样本和未验证项。最后 `docker compose down`，确认采集器停止；模型服务按其他实验需要保留。

追踪实验的停止命令：`docker compose -f labs/observability/tracing.compose.yaml down`。它会丢弃内存中的 traces；先保存需要的记录。
