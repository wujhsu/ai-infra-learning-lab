基础实验需要两张 CUDA <Term id="gpu" label="GPU" /> 与 PyTorch 2.14.0；它使用 PyTorch 安装包实际链接的 <Term id="nccl" label="NCCL" />，脚本打印版本。Device API 是另一个固定 NCCL 2.31.2 的进阶环境，不假定两者版本相同。

## 先手算预期结果

rank 0 输入 `[1,2]`，rank 1 输入 `[2,4]`，<Term id="allreduce" label="AllReduce" /> SUM 后每卡应得到 `[3,6]`。脚本使用 90 秒初始化超时并在结束时销毁通信组。

```bash
torchrun --standalone --nproc-per-node=2 labs/nccl/allreduce.py
```

若失败，先检查设备暴露与 rank 分配，保存所有进程日志。单个 rank 的成功输出不等于整个组通过。

## 跨节点之前检查什么

确保相同 Python、PyTorch、驱动兼容条件与脚本；确认 rendezvous 地址与端口可达；再用明确 node-rank 与节点数量启动。主线预检先检查本地条件，再检查全组通信。

## Device API 进阶路径

使用本地归档 `code/advanced-nccl/` 的固定 commit，先阅读 lsa-simple 和 barrier 的 README。记录 NCCL 2.31.2、CUDA 编译器、GPU、P2P 能力与 <Term id="gin" label="GIN" /> 后端条件。不要将不具备硬件能力的失败当成程序逻辑错误。

为每个 window 写出注册、写入、可见、消费、复用与释放时序。至少覆盖多轮和不同大小；只有 correctness 通过后才能加入计时。

## 验收与清理

提交 rank/world、实际值、预期值、运行时版本和完整退出状态。带宽实验额外区分算法带宽与总线带宽。终止异常运行后检查所有 rank 已退出，避免孤立进程继续占用 GPU。

本站验证过小数组数学预期与脚本语法，但未在本机运行真实 NCCL；不会提供虚构带宽结果。
