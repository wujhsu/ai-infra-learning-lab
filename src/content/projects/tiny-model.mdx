## 你将交付什么

交付一个 7 token 词表、两层 Transformer 的训练检查点，以及生成、缓存一致性和恢复记录。它只对一个教学句子做过拟合，用来验证机制，不声称获得通用中文能力。前置是主线前六章；CPU 即可完成，不需要下载真实模型。

## 建立独立环境

```bash
python3.12 -m venv .venv-training
source .venv-training/bin/activate
python -m pip install -r labs/requirements.txt
python -m unittest discover -s tests -p 'test_tiny_model.py' -v
```

版本为 PyTorch 2.14.0、NumPy 2.4.3。已运行环境为 macOS arm64、Python 3.12.14，完整依赖在 `labs/locks/cpu-macos-py312.txt`。其他平台应安装与设备匹配的 PyTorch 构建；不要把 macOS 的锁文件当作 CUDA 环境。

检查点是五项测试通过：完整与增量计算一致、因果性成立、有限差分与自动梯度一致、保存后继续更新一致、训练损失下降且教学续写正确。如果 import 失败，先确认当前 Python 属于刚创建的环境。

## 读懂最小实现，再训练

`labs/tiny_model/model.py` 的 `TinyLM.forward` 接收形状 `[批次,新位置数]` 的 ID，查 token 和位置向量，经过两层计算，输出 `[批次,新位置数,7]` 的候选得分与各层 KV。位置偏移由历史缓存长度决定。

`train.py` 使用输入 `[0,1,2,3,4,5]`，目标 `[1,2,3,4,5,6]`。目标向前错开一位，是为了让每个位置学习预测下一个 token。训练循环清空梯度、计算交叉熵、反向传播、更新参数；生成循环则不更新参数。

```bash
python labs/tiny_model/train.py --steps 100 --output results/tiny.pt
```

实际 CPU 运行得到训练损失约 `2.59856 → 0.000875`，生成 ID 为 `[0,1,2,3,4,5,6]`，缓存开关生成一致。这是一句训练数据上的检查结果，不是独立验证集成绩；不同数值后端可有小误差。

## 对照两种生成路径

缓存关闭时，每一步重算整个历史；开启时，首轮计算输入，后续只输入新位置并携带各层 KV。测试比较的不只是最后文本，还包括逐位置 logits，避免恰好选到相同 token 掩盖数值错误。

修改练习：把提示改为前两个 token，先预测第一轮缓存长度；再生成两个新 token，解释为什么“返回文本已有的最后一个 token”可能尚未写入缓存。检查一次生成循环究竟先采样还是先把采样结果再次输入模型。

## 中断恢复需要哪些状态

```bash
python labs/tiny_model/train.py --steps 40 --output results/step40.pt
python labs/tiny_model/train.py --resume results/step40.pt --steps 100 --output results/resumed.pt
```

`--steps 100` 是累计目标步数，不是额外训练 100 步。保存内容包括模型配置、参数、AdamW 状态、已完成步数和 CPU 随机状态。当前固定数据、无 dropout 的实验让恢复对照更容易解释；真实随机 DataLoader 与 CUDA 还需要相应状态。

验证时应比较下一步损失与全部参数，而不是只比较文件大小或生成句子。现有测试以相同初始状态分别执行连续更新与保存后更新，检查结果一致。

## 故意破坏一次

去掉缓存位置偏移，观察增量结果从哪里开始偏离；移除因果遮罩，观察前缀不变性测试失败；只加载权重不加载优化器，比较后续参数更新。每次只改一处，写下错误机制，再恢复实现。

不要为了测试通过扩大容差直到掩盖错误。先区分浮点舍入与逻辑不一致，查看最早偏离的位置和层。
