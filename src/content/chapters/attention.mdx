上一章的矩阵乘法逐行处理输入。即使修改“北京”的向量，“的”这一行也没有变化。我们缺少一条数据通路：让当前位置读取其他位置的信息。

现在只取同一段输入的前两项：“北京”“是”。把计算缩到两项，不是换了模型；我们仍使用上一章同一张嵌入表。等看懂两项，再把“中国”“的”放回去。

<span id="weighted-sum"></span>
## 先理解“按比例取信息”

假设两个位置提供的内容向量分别是 `[2,0]` 和 `[0,1]`。我们想汇总它们，但不想让每个位置永远贡献相同比例。如果第一个位置占 1/4，第二个占 3/4，会得到什么？

```text
第一个位置的贡献：(1/4) × [2,0] = [0.5,0]
第二个位置的贡献：(3/4) × [0,1] = [0,0.75]
合在一起：[0.5,0.75]
```

向量乘一个数，就是每个分量都乘它；两个等长向量相加，就是对应分量相加。结果仍是一行两个数，但其中已经含有两个位置提供的信息。

这种计算叫加权求和。“权”就是各项贡献的系数。刚才的 1/4 和 3/4 是我们指定的。真正需要解决的问题是：**怎样根据当前输入，为不同位置计算合适的权重？**

<Term id="attention"/> 正是把“计算匹配权重”与“汇总内容”接起来的一组操作。它不要求人写出“遇到城市就看前面的国家”这种规则，而是通过训练学习数值变换。

<span id="qkv"></span>
## 为什么有三种向量，而不是直接把输入相加？

为当前任务匹配信息的特征，与最后要汇总的内容，不一定是同一组数字。一个朴素类比是查资料：你用检索条件匹配标题或索引，随后读取正文。匹配用的东西与取回的东西可以不同。

这个类比只帮助理解分工。模型中没有显式文字标题或数据库记录，而是三种数值向量：

- <Term id="query"/>：当前位置拿它去与各个位置比较。
- <Term id="key"/>：每个位置提供它，参与匹配得分的计算。
- <Term id="value"/>：匹配权重确定后，真正进入加权汇总的内容。

每个位置通常都会生成自己的 Q、K、V。我们说“当前位置的 Q”，只是此刻只观察一个位置的输出，并不是其他位置永远没有 Q。

它们来自已学过的矩阵乘法：`Q=XWq`、`K=XWk`、`V=XWv`。三张 W 是训练参数。不要被三个字母吓住：把同一行输入送进三种线性变换，就得到三种用途的表示。

本例让 Wq、Wk 都为单位矩阵 `[[1,0],[0,1]]`，即保持输入不变；Wv 使用上一章的 `[[2,0],[0,1]]`。真实模型不会普遍满足这组特殊参数。

| 位置 | 初始向量 | Q | K | V |
|---|---|---|---|---|
| 北京 | `[1,0]` | `[1,0]` | `[1,0]` | `[2,0]` |
| 是 | `[0,1]` | `[0,1]` | `[0,1]` | `[0,1]` |

接下来追踪“是”这一行。它的 Q 是 `[0,1]`，将与两个位置的 K 分别比较，然后汇总两个 V。

<span id="scores"></span>
## 第一步：给每个可读位置算一个匹配分数

两行向量怎样得到一个分数？先看 <Term id="dot-product"/>：对应分量相乘，再把乘积加起来。

```text
“是”的 Q 与“北京”的 K：[0,1] · [1,0] = 0×1 + 1×0 = 0
“是”的 Q 与“是”的 K：  [0,1] · [0,1] = 0×0 + 1×1 = 1
```

得到 `[0,1]` 这组分数。注意两个元素分别对应两个输入位置，不是两个输出词。这里决定的是“从哪里汇总信息”，还没有在词表里选下一个 token。

常见的缩放点积 Attention 还把每个分数除以查询/键向量维度的平方根。本例维度 d=2，所以除以 √2，得到约 `[0,0.7071]`。

为什么需要缩放？当维度增加时，许多乘积的和可能增大，接下来的指数归一化会变得过于偏向少数项。这个缩放为数值尺度提供一种控制。它不是把分数限制到 0 到 1，也不是除以输入 token 数。

<span id="softmax"></span>
## 第二步：把分数转换成可汇总的比例

我们希望比例非负且总和为 1。直接用分数除以其总和不够可靠，因为分数可能为负，总和也可能为 0。<Term id="softmax"/> 先对每个分数取指数，再除以指数的总和。

指数函数记作 exp。现在不需要学习完整的指数函数理论，只用到两点：exp(0)=1；exp(0.7071) 约为 2.0281，并且实数的指数始终为正。

```text
指数值：[1, 2.0281]
总和：1 + 2.0281 = 3.0281
第一个比例：1 / 3.0281 ≈ 0.3302
第二个比例：2.0281 / 3.0281 ≈ 0.6698
```

于是“北京”贡献约 33.02%，“是”贡献约 66.98%。两个比例加起来约为 100%，误差来自显示时四舍五入。

这里高分位置的比例较大，但低分位置并不自动归零。这个特征与只挑一个最大分数位置不同。

<span id="values"></span>
## 第三步：按这些比例汇总 V

现在回到开头学过的向量乘数与相加：

```text
0.3302 × [2,0] + 0.6698 × [0,1]
= [0.6604,0] + [0,0.6698]
≈ [0.6605,0.6698]  # 使用未舍入权重计算后再显示
```

输出仍是一个二维向量。它是“是”位置在这次注意力计算后的表示；还要经过后续处理和输出投影，才会得到下一 token 的词表得分。

<LearningFigure kind="attention" />

现在可以把三种对象严格分开：K 用于计算分数，Softmax 产生位置权重，V 用于汇总。位置权重也不是第一章那组候选 token 概率；二者都可能使用 Softmax，但所归一化的对象不同。

<details>
<summary>把刚才的步骤放回公式</summary>


$$\mathrm{Attention}(q,K,V)=\mathrm{softmax}\left(\frac{qK^T}{\sqrt d}\right)V$$

本例 q 的形状为 `[1,2]`，K、V 均为 `[2,2]`。K 的转置 Kᵀ 把它的每个位置排成一列，所以 q 与 Kᵀ 相乘，恰好得到对两个位置的两个分数，形状为 `[1,2]`。

Softmax 不改变形状，只把这行分数归一化。最终 `[1,2]` 的权重乘 `[2,2]` 的 V，得到 `[1,2]` 的输出向量。公式中的 d 是 Q/K 的分量数，不是位置数。


</details>

<span id="mask"></span>
## 一次处理整段文字，怎样保证不偷看答案？

把四个输入位置全部放回去。训练时，我们可以一起处理“北京”“是”“中国”“的”。但“北京”位置要预测下一项时，不应该偷看已经给出的“是”，否则模型容易依赖生成时根本不存在的未来信息。

<Term id="causal-mask"/> 限制每个位置只能读取自身与更早位置。允许读取的关系如下：

| 当前位置 | 北京 | 是 | 中国 | 的 |
|---|---|---|---|---|
| 北京 | 可读 | 禁止 | 禁止 | 禁止 |
| 是 | 可读 | 可读 | 禁止 | 禁止 |
| 中国 | 可读 | 可读 | 可读 | 禁止 |
| 的 | 可读 | 可读 | 可读 | 可读 |

实现时，通常在 Softmax 之前把不允许的位置对应分数设为负无穷，使其指数成为 0，从而不贡献内容。并不是把输入文本的那些 token 从数组中删除。

这也解释了一个容易混淆的事实：**可以并行计算许多已知输入位置，同时仍然遵守因果依赖。** 能一起处理已知输入，不表示能提前知道尚未生成的未来 token。

## 位置信息与多头：逐步补全真实结构

如果只是对所有位置计算匹配和求和，模型缺少明确处理顺序的方式。真实 Transformer 会按设计加入位置信息。例如位置嵌入给表示加入位置相关数值；RoPE 则根据位置旋转 Q/K 的成对分量，让匹配受相对位置影响。小尺寸示例省略这一步，因此不能用它检验真实模型的位置行为。

多头 Attention 则让不同组 Q/K/V 分别汇总，再把结果组合。一个“头”是一组注意力计算，不是一个 GPU。为什么有时查询头多、KV 头少，会在容量章节结合缓存计数解释；现在先掌握一组计算的数据流。

常见真实层还会保留输入的残差路径、调整数值尺度、逐位置进行前馈加工。项目中的极小模型会显式实现这些部件，帮助你从这一组算式走到完整可训练程序。

## 改一个数字，看看变化从哪里传过去

保持 Q/K 不变，只把“北京”的 V 从 `[2,0]` 改成 `[4,0]`。匹配分数是否改变？权重是否改变？输出的第一个分量是否改变？

<details>
<summary>展开推理</summary>


分数只读 Q/K，因此不变；Softmax 权重也不变。最后汇总读 V，所以输出的第一个分量约从 0.6605 变成 1.3210。这个修改帮助你分清匹配与内容两条路径。真实模型中改输入 X 可能同时改变 Q/K/V，不能只套用本题“保持 Q/K 不变”的结论。


</details>
