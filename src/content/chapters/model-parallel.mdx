数据并行让不同进程处理不同样本，状态分片则改变存储所有权。还有一些情况需要把一次模型计算本身拆给多张卡。这一章用同一层矩阵乘法和层序列区分几种方式。

## 张量并行：一起完成一层

若输出是 `Y=XW`，可以按 W 的输出列切分。各卡拿相同输入 X，分别计算一部分输出列，再按后续需要收集或继续使用分片。

也可以按归约维度切分：各卡计算输出的一部分和，再把部分结果相加。不同切分方式对应不同通信，不能只说“矩阵切成两半”而不说明沿哪一维。

张量并行 TP 往往在层内频繁交换数据，因此对互连和细粒度延迟较敏感。切分还要与注意力头、隐藏维度等结构相容，并非任意卡数都能直接应用。

## 流水线并行：不同设备负责不同层

把前几层放到设备 A，后几层放到设备 B。一个微批次先过 A，再把激活交给 B。单个微批次仍按依赖前进，但多个微批次可以在不同阶段流水执行。

训练还需要反向传播：后段产生的输入梯度要传回前段。流水线的调度方式决定哪些时刻执行前向或反向，以及需要保留多少激活。

填充与排空产生 bubble，也就是部分阶段空闲的区间。微批次更多可能改善利用率，却可能增加调度和状态管理开销。阶段计算不均衡时，最慢阶段会限制吞吐。

## 专家并行：按路由把 token 送到不同计算块

<Term id="moe"/> 使用路由选择部分专家参与每个 token 的处理。专家可以分布在不同设备上；输入先按目标专家发送，计算后再把结果组合回来。

专家并行 EP 因此涉及数据重新分组与跨设备交换，常出现 AllToAll 类通信。若某些专家接到特别多的 token，负载会不均；稀疏激活不代表每张卡都一样忙。

模型总参数很多但每 token 只激活部分参数，会影响计算与存储的关系。不能用“每次只算两个专家”推断只需要加载两个专家的全部模型存储。

## 数据并行、张量并行和流水线如何组合？

一个作业可以先组成多个模型并行组，每组协作完成一份模型，再让不同组处理不同数据。这时通信组有不同范围：某次 collective 可能只在 TP 组内，梯度同步则跨相应数据并行组。

所以同一个全局 rank 会属于多个通信组，不能把全作业 world size 代入每个操作。源码和日志里应明确当前组的成员与作用。

使用 DeviceMesh 等抽象可以描述设备的多维组织，但抽象仍需要映射到真实硬件拓扑。逻辑上相邻，不保证物理互连最快。

## 一张表帮助选择，不能代替实验

| 方法 | 主要切分对象 | 典型代价 |
|---|---|---|
| 数据并行 | 不同样本 | 梯度同步与模型副本 |
| 状态分片 | 参数/梯度/优化器状态 | 收集、分散与临时峰值 |
| 张量并行 | 一层中的张量计算 | 细粒度层内通信 |
| 流水线并行 | 模型层或阶段 | 激活传输、流水线空隙 |
| 专家并行 | 不同专家 | 路由交换、负载不均 |

先问约束是单卡容量、计算吞吐还是互连，再选择候选组合。还要看任务规模：一个很小模型跨很多卡运行，通信开销可能远大于节省的计算时间。

## 训练与推理不必使用同一种并行配置

训练要反向和更新，常有较大批次；推理要满足请求延迟，KV 和动态长度又成为额外约束。训练时最优的拓扑或并行度，不保证在线服务最优。
