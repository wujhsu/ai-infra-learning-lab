## 这一章解决什么问题

前四章的模型都自带一组已经存在的参数：词向量表、Q/K/V 投影、输出层。你能解释这些数怎样参与计算，但还不知道它们最初从哪里来、又怎样被一步步改到"正确"。

本章只回答一个问题：模型怎样知道参数该往哪边改？

这个问题可以拆成三小步，每一步都对应本章的一块内容：

- 怎样把"错"变成一个数？——<Term id="loss"/>。
- 往哪个方向改，改一点点会怎样？——<Term id="gradient"/>。
- 一步改多少，由谁来执行？——学习率与 <Term id="optimizer"/>。

路线如下。先用一个只有单个参数的预测问题，把"从损失到一次更新"完整手算到底，每个数字都写出来。再用有限差分独立复核同一个梯度——这是本章 Lab 卡片里那条真实测试用的方法。然后把链式法则放到两层小网络上，看清 <Term id="backprop"/> 到底在算什么。最后读真实训练代码 `train_step` 的四行核心，确认它做的正是你手算的这件事，并留一步更新给你自己走。

读完的检验标准：不看正文，能复述参数 w 从 2 到 2.8 再到 2.96 的每一步数字是怎么来的。

## 机制讲解：把一次更新从头算到尾

### 第一步：给模型一个可测量的错

预测函数取最简单的形式：`预测值 = w × 输入值`，w 是唯一待学习的参数。输入取 2，希望输出 6；初始 w=2。

损失把"这次预测错多少"压成一个数。先取平方误差：

```text
预测  y = w × x = 2 × 2 = 4
损失  L = (y − 目标)² = (4 − 6)² = 4
```

平方使正负方向的错误都产生非负损失，而且差得越多罚得越重。损失的形式由任务定义：这个例子的目标、公式和单位是我们规定的，损失值不是天然可跨任务比较的"模型分数"；训练任务换了，同一个数值的含义也会变。

现在有了一个可以下手改的量：参数 w 动一点，L 会怎么动？

### 第二步：解析梯度：dL/dw = −8

梯度回答"微小改动参数时，损失如何变化"。只有一个参数时，它就是一个导数；很多参数时，是每个参数各自的变化率排成的一组数。

L = (w × x − t)²。令 y = w × x，则 L 对 y 的变化率是 2(y − t)，y 对 w 的变化率是 x，两段影响相乘：

```text
dL/dw = 2 × (y − t) × x = 2 × (4 − 6) × 2 = −8
```

−8 的读法：在 w=2 附近，w 每增加 1，损失约下降 8；w 减小则损失上升。方向信息在符号里，陡峭程度在绝对值里。这就是"参数该往哪边改"的直接答案。

### 第三步：有限差分：不靠求导规则，复核 −8

导数不神秘的一面：它就是"改动一点点，看损失变多少"。你也可以直接试。

先试一个粗糙的步长 0.01：w=2.01 时，预测 4.02，损失 (4.02−6)² = 3.9204；w=1.99 时，预测 3.98，损失 4.0804。用前向差商估计变化率：

```text
(3.9204 − 4) / 0.01 = −7.96
```

接近 −8 但不等于 −8，因为 0.01 这一步走得不够小。把步长缩到 ε = 0.00001，并在 w 两侧对称地各算一次：

```text
L(w + ε) = (2 × 2.00001 − 6)² = (−1.99998)² ≈ 3.99992
L(w − ε) = (2 × 1.99999 − 6)² = (−2.00002)² ≈ 4.00008

中心差商 = (3.99992 − 4.00008) / (2 × 0.00001)
        = (−0.00016) / 0.00002
        = −8
```

与解析梯度一致。这种对称取两侧的算法叫中心差分，它的 ε² 误差项在相减时恰好抵消；本例的损失是二次函数，所以不止"近似相等"，而是精确相等——把上面两式多写几位是 3.9999200004 与 4.0000800004，末尾两个 4×10⁻¹⁰ 也互相抵消。

有限差分只依赖"能算出损失"这一件事，不依赖任何求导公式。所以它常被当作裁判：自动求导实现错了，它未必能发现；但两条路径的结果对不上，就一定有一边是错的。本章 Lab 卡片引用的真实测试，用的正是这个办法。

它也有明确的代价：每验证一个参数，就要额外完整地正向计算两次损失。真实模型有上百万、上亿个参数，逐个有限差分不可行；反向传播一次 backward 就把所有参数的梯度一起算完。所以训练用反向传播，有限差分留给测试里抽查个别参数——前面两层小网络里"dL/dy=4 被两个参数共享"，正是这种一次算全的雏形。

### 第四步：一步更新：w 从 2 到 2.8

知道方向后还要决定步长。最简单的更新规则（梯度下降）是：

```text
新 w = 旧 w − 学习率 × 梯度
```

梯度指着损失上升的方向，所以朝反方向走；学习率是人为设置的步长系数，本例取 0.1。

```text
新 w    = 2 − 0.1 × (−8) = 2.8
新预测  = 2.8 × 2 = 5.6
新损失  = (5.6 − 6)² = 0.16
```

一次更新把损失从 4 压到 0.16，但还没到 0：最优点在 w=3，现在还差 0.2。步长选错会怎样？学习率取 1 时，新 w = 2 − 1 × (−8) = 10，预测 20，损失 196，比出发时差得多。梯度只保证当前点的局部方向，步子太大可能直接跨过谷底。

<GradientDemo client:visible />

这也是"梯度下降"不保证每一步、每个样本都下降的原因之一。真实训练从小批次估计梯度，方向本身有噪声；目标函数也远比一个二次抛物线复杂，还存在数值误差。

### 链式法则在两层小网络上：反向传播在算什么

单参数的 dL/dw 一行写完。模型里有成千上万个参数，靠的是同一条链式法则的重复应用。看一个两层的小网络，仍然只用标量：

```text
第 1 层：h = w1 × x
第 2 层：y = w2 × h
损失　：L = (y − t)²
```

取 x=2、w1=2、w2=3、目标 t=10。先正向：

```text
h = 2 × 2 = 4
y = 3 × 4 = 12
L = (12 − 10)² = 4
```

反向传播从损失往回走，逐段相乘：

```text
dL/dy  = 2 × (y − t) = 2 × 2 = 4
dL/dw2 = dL/dy × dy/dw2 = 4 × h = 4 × 4 = 16
dL/dw1 = dL/dy × dy/dh × dh/dw1 = 4 × w2 × x = 4 × 3 × 2 = 24
```

注意两件事。第一，算 dL/dw2 需要正向留下的 h=4，算 dL/dw1 需要 w2 和 x：反向传播要读取正向的中间值。这就是训练往往要保留更多激活的原因——反向计算还会用到它们。

第二，dL/dy=4 这一段被两个参数共享。反向传播的效率来自从损失出发走一遍、顺便算出所有参数的梯度，而不是对每个参数单独从头推一遍。

PyTorch 的自动求导做的正是这件事：记录正向运算的依赖，在 `backward()` 时沿图反向组合每种运算自己的求导规则。单参数例子放进去只有几行：

```python
import torch
w = torch.tensor(2.0, requires_grad=True)
loss = (w * 2.0 - 6.0) ** 2
loss.backward()
print(w.grad.item())   # -8.0
```

`requires_grad=True` 声明希望对这个量求梯度；`backward()` 只计算并累积梯度，不会自动更新 w。自动求导替你组合数值求导规则，并没有替你选择正确的损失、数据或训练目标。

### 优化器：step 之前，梯度只是建议

有了梯度，最后一环是由谁来改参数。优化器接管更新。SGD 用的就是刚才的规则：更新量 = 学习率 × 梯度。AdamW——本项目 `train.py` 用的就是它，学习率 0.01——还维护每个参数自己的梯度一阶矩、二阶矩统计，按参数自适应调整步长，并附加权重衰减。这些额外数值叫优化器状态：占内存，恢复训练时也必须一并恢复，否则后续更新就走样。

关键在分工：`backward()` 结束后，参数一个都没变。梯度只是写进 `p.grad` 的一组"建议"；要等 `optimizer.step()` 按 SGD 或 AdamW 各自的规则消费这些建议，参数才真正更新。这也回答了本章开头的问题——backward 之后损失当然不变：旧 loss 张量记录的是更新前那次正向的结果，要看到新损失，得用更新后的参数重新正向计算一次。

SGD 与 AdamW 的差别还会落到基础设施上。SGD 没有隐藏状态，梯度用完即弃；AdamW 为每个参数维护一阶矩和二阶矩两个统计，训练状态比参数本身还要多占一份内存，而且必须随检查点一起保存、随恢复一起加载。后面讲训练内存和检查点的章节会回到这笔账，这里先记住结论的来源：优化器更新的不只是参数，还有自己的统计。

## 代码走读：train_step 的四行核心

`labs/tiny_model/train.py` 的 `train_step` 是真实训练循环的心脏。把它的每一行和手算对上：

```python
def train_step(model, optimizer):
    model.train()
    optimizer.zero_grad(set_to_none=True)
    logits, _ = model(INPUT)
    loss = F.cross_entropy(logits.reshape(-1, len(TOKENS)), TARGET.reshape(-1))
    loss.backward()
    optimizer.step()
    return loss.item()
```

| 代码行 | 手算里的对应 |
| --- | --- |
| `optimizer.zero_grad(set_to_none=True)` | 开始新一轮，清掉上一轮梯度 |
| `logits, _ = model(INPUT)` | y = w × 2：用当前参数做一次正向 |
| `loss = F.cross_entropy(...)` | L = (y−目标)²：输出与目标压成一个数 |
| `loss.backward()` | dL/dw = −8：沿计算图反向，建议写进 `.grad` |
| `optimizer.step()` | w ← 2 − 0.1 × (−8) = 2.8（AdamW 按自己的状态消费梯度） |
| `return loss.item()` | 汇报更新前那次的 L=4，不是更新后的 0.16 |

顺序非常重要。PyTorch 的梯度默认累加：不清理就继续反向，两轮的 −8 会加成 −16。有时我们正是要利用累积来模拟更大批次，但那需要刻意设计，而不是忘了清理。

`train_step` 里没出现的两个常量也是手算例子的直系后代。`INPUT` 是 `[北京, 是, 中国, 的, 首都, 。]` 六个 ID，`TARGET` 是同样六个位置各自错开一位的目标：模型在每个位置都要预测下一项。手算里"输入 2、目标 6"是它的单参数缩微版。

这里的损失不再是平方误差，而是交叉熵，因为语言模型的目标是"下一个 token 是谁"：每个位置对 7 个词表候选给分，交叉熵惩罚分给目标 token 的概率过低。单个位置可写为 `L = −ln(p_target)`——目标概率 0.5 时损失约 0.693，提高到 0.9 时约 0.105。INPUT 与 TARGET 错开一位，因果遮罩保证每个位置看不到后面的目标，于是 6 个位置的监督信号一次正向同时完成。logits 直接交给 `F.cross_entropy`，由它稳定地完成相应计算；不要先做一遍 Softmax 再把概率当 logits 传入。

最后请出裁判。`tests/test_tiny_model.py` 里那条梯度对照测试的核心九行，用的正是前面中心差分的算法：

```python
    def test_gradient_matches_finite_difference(self):
        self.model.double()
        def loss():return torch.nn.functional.cross_entropy(self.model(INPUT)[0].reshape(-1,7),TARGET.reshape(-1))
        loss().backward();p=self.model.head.weight
        analytic=p.grad[0,0].item();eps=1e-5
        with torch.no_grad():
            original=p[0,0].item();p[0,0]=original+eps;plus=loss().item()
            p[0,0]=original-eps;minus=loss().item();p[0,0]=original
        self.assertAlmostEqual(analytic,(plus-minus)/(2*eps),places=6)
```

读法：`self.model.double()` 先把参数换成 float64——两个损失之差只有 1.6×10⁻⁴ 量级，还要对到小数点后 6 位，float32 的舍入误差会淹没它。`loss().backward()` 得到自动求导的 `analytic`。随后在 `no_grad` 区域里，把 `head.weight` 的同一个分量 `p[0,0]` 手动加 ε、减 ε 各算一次损失，`(plus−minus)/(2*eps)` 就是手算里 `(3.99992−4.00008)/0.00002` 那一步；算完把参数改回原值。两条完全不同的路径得到同一个数，"参数该往哪边改"这件事才算被验证，而不只是被声明。

## 动手：再走一步 gradient descent

上一节停在 w=2.8、损失 0.16。继续用学习率 0.1，把下一步自己走完：

1. 用 w=2.8 重新计算预测 y 和损失 L，确认得到 0.16。
2. 计算这一点的新梯度 dL/dw（公式不变：2 × (y−t) × x）。
3. 用更新规则算出新 w。
4. 计算新 w 对应的预测和损失。

先全部手算，再展开核对：

<details>
<summary>展开核对</summary>


```text
第 2 步：dL/dw = 2 × (5.6 − 6) × 2 = −1.6
第 3 步：新 w = 2.8 − 0.1 × (−1.6) = 2.96
第 4 步：新预测 = 2.96 × 2 = 5.92，新损失 = (5.92 − 6)² = 0.0064
```

完整链条：w=2 → 梯度 −8 → w=2.8（L=0.16）→ 梯度 −1.6 → w=2.96（L=0.0064）。

再观察一个规律。最优点在 w=3，到它的距离从 1 缩到 0.2 再到 0.04，每步恰好乘 0.2；损失与距离的平方成正比，所以每步乘 0.04：4 → 0.16 → 0.0064。学习率 0.1 时，这个二次函数上每步等比例收缩。这不是普遍规律，但它给出"训练曲线先快后慢"的直觉来源：越接近谷底，梯度越小，同样的学习率迈出的步子也越小。


</details>

最后留一个本章没有展开、但训练永远躲不开的问题：训练损失下降，只说明模型在拟合见过的数据，它可能只是记住了样本。所以还要在没有参与更新的验证数据上观察表现；训练集、验证集与测试集的边界，要在处理数据时就划清，不能把几乎重复的段落随机分到两侧后就认为验证严格。
