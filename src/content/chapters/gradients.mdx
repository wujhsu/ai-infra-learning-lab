前四章都假定参数已经存在。你可能已经能解释模型如何生成，却还不知道这些数从哪里来。现在让模型犯一个可测量的小错误，然后用错误改变参数。

先用只有一个参数的函数学习更新机制，再把它放回语言模型。这样你不必在第一次理解导数时，同时处理几百万个数。

## 给模型一个目标，才知道什么叫“错”

假设预测函数为 `预测值 = w × 输入值`，w 是待学习的参数。给定输入 2，希望输出 6；初始 w=2，所以预测为 4。

<Term id="loss"/> 把预测与目标之间的差异压成一个数。我们先取平方误差：`L=(预测−目标)²`，于是 L=(4−6)²=4。差值平方使正负方向的错误都产生非负损失。

这个例子的目标、公式和单位由任务定义。损失值不是天然可跨任务比较的“模型分数”；训练任务换了，损失的意义也可能变化。

## 怎样判断 w 应该增加还是减小？

你可以先试两次：w=2.01 时，预测 4.02，损失约 3.9204；w=1.99 时，预测 3.98，损失约 4.0804。附近增大 w 能让损失下降。

这就是局部变化率的直觉。<Term id="gradient"/> 将这种“微小改动参数时损失如何变化”的关系计算出来。只有一个参数时，它就是一个导数；很多参数时，把对每个参数的变化率组成一组数。

从有限小步近似来看：`(3.9204−4)/0.01 = −7.96`。步长足够小时，这个变化率靠近 −8。负号表示在当前点稍微增大 w，损失倾向下降。

<aside class="concept-note">
<strong>不用记规则，也能看懂这个导数怎样得到</strong>


令 y=wx，L=(y−t)²。L 对 y 的变化率为 `2(y−t)`；y 对 w 的变化率为 x。两段影响连起来，得到 `dL/dw=2(y−t)x`。

代入 x=2、t=6、w=2：`2×(4−6)×2=−8`。把沿途变化率相乘叫链式法则。它回答“参数先影响中间值，中间值再影响损失，总影响怎样组合”。


</aside>

## 有了梯度，再决定走多远

最简单的梯度下降更新为：`新 w = 旧 w − 学习率 × 梯度`。学习率是人为设置的步长系数；本例取 0.1。

```text
新 w = 2 − 0.1 × (−8) = 2.8
新预测 = 2.8 × 2 = 5.6
新损失 = (5.6−6)² = 0.16
```

一次更新把损失从 4 降到 0.16，但还没恰好到目标。如果学习率取 1，新 w=10，预测 20，损失变成 196，反而更差。梯度方向有局部意义，过大的步长可能跨过好的区域。

这也解释为什么“梯度下降”不保证每一步、每个样本或验证集指标都下降。真实训练从小批次估计梯度，目标复杂，还存在数值误差。

## 从一条计算链到计算图

模型会执行许多相互依赖的运算。把中间值与运算连成图，就得到计算图。<Term id="backprop"/> 沿图反向应用链式法则，把最终损失的影响传播回参数。

“反向”不是把正向程序倒着执行一遍，也不是简单把矩阵转置。每种运算有自己的求导规则，需要用到正向中的某些中间值。这就是训练往往要保留更多激活的原因：反向计算还会读取它们。

PyTorch 的自动求导会记录需要梯度的运算依赖，在调用 `backward()` 时计算梯度。自动求导替你做数值求导规则的组合，并没有替你选择正确的损失、数据或训练目标。

```python
import torch
w = torch.tensor(2.0, requires_grad=True)
prediction = w * 2.0
loss = (prediction - 6.0) ** 2
loss.backward()
print(w.grad.item())  # 预期 -8.0

with torch.no_grad():
    w -= 0.1 * w.grad
print(w.item())       # 约 2.8，浮点显示可能略有误差
```

`requires_grad=True` 表示希望计算这个量的梯度。`backward()` 计算并累积梯度，并不会自动更新 w。更新动作放进不记录梯度的区域，避免把训练规则本身接回本轮求导图。

## 优化器是在这个位置进入的

<Term id="optimizer"/> 接管参数更新。随机梯度下降 SGD 可以使用刚才的规则；Adam 类优化器还维护梯度一阶、二阶统计，按参数调整更新。这些额外数值叫优化器状态，会占内存，也需要在继续训练时正确恢复。

```python
optimizer.zero_grad(set_to_none=True)  # 清掉上一轮梯度
loss = compute_loss(model, batch)      # 正向计算
loss.backward()                       # 反向计算梯度
optimizer.step()                      # 按规则更新参数
```

这是流程伪代码。顺序非常重要：如果不清理而继续反向，梯度会累积；有时我们正是要利用累积模拟更大批次，但那需要刻意设计，而不是忘了清理。

## 语言模型的目标不是一个数，而是正确的下一项

回到“北京是中国的首都”。在已知前文后，训练数据给出下一 token 的目标。模型为词表给出得分，交叉熵损失会惩罚分配给目标 token 的概率过低。

对于单个目标，损失可以写为 `L=−ln(p_target)`。ln 是自然对数。目标概率为 0.5 时损失约 0.693；提高到 0.9 时损失约 0.105。因为训练希望压低这个损失，参数更新会推动模型在相似上下文下提高目标的概率。

通常直接把原始 logits 交给库的交叉熵函数，由它稳定地完成相应计算；不要未经核对先做一次 Softmax，再把概率当 logits 传入。

训练可以同时计算一段样本中多个位置的目标损失。因果遮罩确保每个位置不能偷看后面的目标。生成时未来 token 未知，需要逐步产生；训练时整段样本已知，可以一次组织多个位置的监督信号。

## 训练损失下降之后，还要问什么？

模型可能只记住训练样本，所以还要在没有参与更新的验证数据上观察表现。训练集、验证集与测试集的边界要在处理数据时明确，不能把几乎重复的段落随机分到两侧后就认为验证严格。
