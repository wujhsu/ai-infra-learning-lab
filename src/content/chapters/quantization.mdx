假设权重和 KV 的显存账本已经解释了为什么模型装不下。现在我们尝试让每个数占用更少的位。这个动作改变了数据表示，可能也改变计算路径；因此必须分别回答三个问题：省下多少字节、引入多大误差、硬件是否能更快执行。

## 先把一个数存得更粗

<Term id="quantization" /> 的简单形式，是选择步长 s，把实数 x 映射到整数 q。采用对称量化、零点为 0 时：

$$q=\operatorname{clip}(\operatorname{round}(x/s),q_{min},q_{max}),\qquad \hat{x}=s q.$$

x 与还原值同单位；s 是每个整数刻度对应的实数间隔；q 无量纲。clip 把越界结果截到可表示范围。现在 s=0.1，x=0.26，得到 q=3，还原为 0.3，绝对误差 0.04。x=-0.24 得到 q=-2，还原为 -0.2，误差也是 0.04。

如果可表示整数只有 -2 到 2，0.26 会被截为 2，还原为 0.2。取整误差与范围截断是两种不同原因。增加范围往往需要加大步长，从而降低小数的分辨能力。

```python
# 教学编码器：用于检查数值关系，不是高性能推理 kernel。
def encode(x, scale, low=-127, high=127):
    q = max(low, min(high, round(x / scale)))
    return q, q * scale
print(encode(0.26, 0.1))  # (3, 0.30000000000000004)
```

最后的小数尾差来自 Python 的二进制浮点表示，不是又出现了一种量化方案。

## 误差怎样进入模型计算

设输入 x=[1,2]，原权重 w=[0.26,-0.24]。点积是 -0.22。用上面的还原值 [0.3,-0.2] 计算，得到 -0.1，结果误差为 0.12。权重每项误差不大，经过乘加和后续层，输出误差仍可能改变候选 token 的排序。

因此，权重的平均误差不能单独代表生成质量。某些通道的异常大值会拉大整组尺度；按通道或按组设置尺度可以改善局部精度，但要多存元数据。校准数据用于观察真实激活范围或优化量化决策；它必须接近目标负载，并与最终质量评测集分开。

## W4A16 到底省了什么

W 表示权重，A 表示激活；W4A16 表示权重以 4 位形式存储或参与指定方案，激活采用 16 位。它没有承诺 KV 也是 4 位，也没有承诺所有计算都使用整数乘法。

理论上，十亿个权重从每个 2 字节降到半字节，由约 2 GB 降到约 0.5 GB。这只是权重主体；还要加尺度、零点、分组元数据、未量化层、运行时工作区和 KV。十进制 GB 与 GiB 不要混算。

低位权重可能在执行前解包，或者通过融合 kernel 边读取边解量化。若当前 GPU、形状和后端没有合适 kernel，节省显存也可能付出更多计算时间。真实支持需要检查引擎版本、GPU 架构、量化格式和模型结构四者的组合。[vLLM 支持矩阵](https://docs.vllm.ai/en/latest/features/quantization/)

<details>
<summary>FP16、BF16、FP8 与整数是不是一回事？</summary>

浮点数用指数和有效数字覆盖不同数量级；整数加尺度是在一个量化区间内映射。BF16 与 FP16 都是 16 位，但指数与有效数字分配不同。FP8 也有不同格式。位数相同不意味着动态范围、误差或硬件执行相同，比较时必须写完整格式。

</details>

## 为什么 KV 量化要单独检查

KV 是每个位置每层保存的中间状态。降低它的精度可以容纳更多历史与并发，但误差参与后续 Attention。长上下文里重复读取的范围更大；短问答质量不变，不能证明长文定位也不变。

要分别做权重量化和 KV 量化对照，再尝试组合。否则一个设置出现回归时，难以判断来源。缓存键与可复用布局也必须匹配精度及尺度配置，不能把两种 KV 格式当作同一块数据。

## 一张合格的比较表

先固定未量化基线、模型 revision、tokenizer、提示模板、数据集和随机设置。每次只改变量化方案，记录权重大小、峰值显存、TTFT、输出 token 间隔、吞吐以及质量指标。质量至少包括任务正确率、结构化输出通过率和长上下文专项；需要人工判断时保存盲评规则。

例如，A 的吞吐比基线高 20%，但关键业务字段正确率从 99% 降到 94%，不能把它写成“优化成功”。相反，一个不提速但让模型从无法部署变成可在目标设备运行的方案，也可能具有明确价值。
