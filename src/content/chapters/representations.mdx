上一章，我们把“北京是中国的”变为 `[0,1,2,3]`，再用一个暂时没有展开的 `model(context_ids)` 函数给候选打分。这一章打开这个函数的第一层：**模型内部处理的，为什么不是这四个编号本身？**

先回忆一个约定：编号只是词表中的身份。ID 2 与 ID 3 相差 1，没有理由意味着“中国”和“的”只差一点点词义。如果直接把 ID 大小当作语言特征，编号怎么安排就会错误地决定意义。

我们需要另一种表示：让每个 token 对应一组可以参与运算的数值，而且这些数值能够在训练中调整。

<span id="vectors"></span>
## 向量先当作一行有顺序的数字

<Term id="vector"/> 是按顺序排列的一组数字。`[1,0]` 就是一个二维向量：“二维”在这里表示有两个分量，不要求你想象几何空间。第一个分量是 1，第二个是 0。

为什么不只给每个 token 一个数？一个数的表达空间太有限。使用一组数字后，后续计算可以用不同组合表示和区分输入的特征。实际模型通常使用远多于两个分量的表示；我们缩到两个，是为了每一步都能手算。

但不要给这两个坐标贴上“城市程度”和“国家程度”之类固定标签。真实模型学到的表示通常不能被这样逐项翻译成人话。**数值能支持后续任务，不代表每个数都有一个可直接命名的语义。**

<span id="embedding"></span>
## 从 ID 查到向量：第一次看见模型参数

我们给七个 token 配上下面的二维向量。整张表叫嵌入表，按 ID 从中查出向量叫 <Term id="embedding"/>。

| ID | token | 本例的初始向量 |
|---|---|---|
| 0 | 北京 | `[1,0]` |
| 1 | 是 | `[0,1]` |
| 2 | 中国 | `[1,1]` |
| 3 | 的 | `[0,2]` |
| 4 | 首都 | `[2,0]` |
| 5 | 。 | `[0,0]` |
| 6 | 结束标记 | `[0,0]` |

这些数是为了教学手工填写的，没有训练，也不具有真正的中文续写能力。尤其是后两项相同，意味着这个极小示例无法仅靠初始向量区分它们；这正是简化模型的限制。

现在输入 ID 0，就取第 0 行得到 `[1,0]`。输入 ID 2，就取第 2 行得到 `[1,1]`。这不是把数字 2 做了某种自然语言计算，而是**用编号选择训练参数表中的一行**。

词表与嵌入表分工不同：词表负责“哪个 token 是哪个编号”，嵌入表负责“这个编号对应怎样的数值表示”。换一个编号体系而不同时调整对应关系，就会查错行。

嵌入表本身属于上一章所说的 <Term id="parameters" context="这里具体指嵌入表中的数值。真实模型在训练时可以更新这些数；普通推理时根据输入 ID 读取相应行。"/>。收到一条新请求时，不是临时为每个词随机创造一组数，而是使用已经确定的表。

<span id="shape"></span>
## 四个位置，每个两个数字：形状为什么重要？

按顺序查出输入的四行，就得到：

```text
X = [ [1, 0],   ← 位置 0：“北京”
      [0, 1],   ← 位置 1：“是”
      [1, 1],   ← 位置 2：“中国”
      [0, 2] ]  ← 位置 3：“的”
```

它有 4 行、2 列，所以形状是 `[4,2]`。第一维数位置，第二维数每个位置的分量。总共存了 `4 × 2 = 8` 个数。**形状描述怎样组织数据，里面真正存的值是上面那八个数。**

这种带形状的数字数组叫 <Term id="tensor" context="当前的张量 X 是四行两列：每行对应一个输入位置，每列对应表示中的一个分量。"/>，中文叫张量。向量可以看成一维张量，矩阵可以看成二维张量。你不需要先学抽象张量代数，才能阅读这里的代码。

如果同时处理两条长度都为 4 的输入，可以多出一个维度，写成 `[2,4,2]`：两条序列，每条四个位置，每个位置两个分量。它一共有 `2 × 4 × 2 = 16` 个数。后面看到模型代码中的三维、四维数组，先问每一维在数什么。

形状还不直接告诉你占多少字节。若这里每个数按 4 字节存储，`X` 的原始数值数据占 `8 × 4 = 32` 字节；若每个数按 2 字节存储，则是 16 字节。这只是数据本身，不包括语言对象等额外开销。显存章节会把这种计数放大到真实模型规模。

<details>
<summary>为什么不能把 [4,2] 随便改成 [2,4]？</summary>


两者都是八个数，但含义不同。我们约定一行对应一个位置；改成两行四列，就成了两个位置、每个四个分量。某些代码允许重新排列形状，但语义是否仍正确，要由算法决定。元素数量相等，不保证可以互换使用。


</details>

<span id="matrix"></span>
## 亲手完成一次矩阵乘法

查表只是起点。模型还会对这些数字进行转换。先用一个极小的权重矩阵 `W` 演示：

```text
W = [ [2, 0],
      [0, 1] ]
```

为了看清规则，我们先只拿“中国”的一行 `x = [1,1]`。计算 `y = xW` 时，**拿 x 的一行，分别与 W 的每一列配对**：

```text
y 的第一个数 = 1×2 + 1×0 = 2
y 的第二个数 = 1×0 + 1×1 = 1
所以 y = [2,1]
```

每个输出数都要先乘再加。这个过程叫 <Term id="matmul"/>。它不是把两个矩阵相同位置的元素逐个相乘；两种运算在代码里也是不同操作。

把输入的四行分别做同样的事：

| token | 输入行 x | 输出行 xW |
|---|---|---|
| 北京 | `[1,0]` | `[2,0]` |
| 是 | `[0,1]` | `[0,1]` |
| 中国 | `[1,1]` | `[2,1]` |
| 的 | `[0,2]` | `[0,2]` |

这次转换恰好把第一个分量乘以 2，保留第二个分量。真实权重通常更复杂，会混合不同分量，而不只是放大其中一项。先用简单数字学会追踪规则，再扩大规模。

这里，输入 `X` 的形状是 `[4,2]`，权重 `W` 是 `[2,2]`，输出还是 `[4,2]`。你可以把它读作：“每行取两个输入分量，计算两个输出分量；一共重复四行。”

<details>
<summary>把这个规则概括为公式</summary>


若 `X` 的形状是 `[n,d]`，`W` 的形状是 `[d,m]`，则 `Y=XW` 的形状是 `[n,m]`。

- `n`：位置数，也就是行数。
- `d`：每行的输入分量数。
- `m`：每行的输出分量数。

$$Y_{ij}=\sum_{k=1}^{d}X_{ik}W_{kj}$$

`i` 选择输入的哪一行，`j` 选择输出的哪一列，`k` 依次经过参与相乘的输入分量。求和符号表示把这 `d` 个乘积相加。这些数值在本例没有物理单位；维度表示元素个数，不是米或秒。


</details>

## 看一次能运行的计算

下面只使用 Python 标准功能。它的目的，是核对上一节的四行结果，不是在运行一个真正语言模型。

```python
X = [[1, 0], [0, 1], [1, 1], [0, 2]]
W = [[2, 0], [0, 1]]

Y = [
    [sum(row[k] * W[k][j] for k in range(2))
     for j in range(2)]
    for row in X
]
print(Y)
# 预期：[[2, 0], [0, 1], [2, 1], [0, 2]]
```

最外层循环逐行处理输入；`j` 选择输出列；`k` 完成那次“逐项相乘再相加”。如果你会后端编程，这些循环都很普通。GPU 的作用之一，是让规模大得多的数值运算高效执行；数学关系不会因为搬到 GPU 上就变成另一套规则。

<span id="layers"></span>
## 一个模型为什么需要许多层？

刚才的矩阵乘法对每行独立执行。把前面的“北京”换成别的 token，“的”这一行仍是 `[0,2]`，经过这个 `W` 后也不变。**只做这种逐行转换，当前位置就还没有从其他位置获得信息。**

语言理解显然需要上下文。同一个词出现在不同句子里，所指对象或作用可能不同。我们需要一种操作，把前面位置的信息带到当前位置；下一章的 Attention 就负责完成这种跨位置的信息汇总。

在常见的 Transformer 语言模型中，一层并不等于只乘一次矩阵。可以先将一层理解为一段有固定结构的数值处理流程：一部分用 Attention 汇总其他位置的信息，另一部分对各位置的表示继续加工。这样的层反复堆叠，后一层读取前一层的结果。

逐位置加工的部分经常叫前馈网络或 MLP。它包含矩阵运算和非线性操作；“非线性”在这里意味着整个过程不能简单压成一次固定矩阵乘法。现在知道它参与继续转换表示即可，暂不需要理解各种激活函数。

层中还常见残差连接与归一化。前者把进入某段计算前的表示加回其输出，让已有信息保留一条直接路径；后者按规定方式调整数值尺度。我们先标出它们在地图中的角色，本章的小矩阵没有模拟一个完整的真实 Transformer 层。

```text
输入 ID
  ↓ 查嵌入表，并按模型设计处理位置信息
初始数值表示
  ↓ 多层处理：跨位置汇总 + 逐位置加工
结合上下文的数值表示
  ↓ 输出投影：转换为词表中各候选的得分
最后位置的候选得分
  ↓ 使用上一章的选择规则
下一个 token ID
```

输入经过计算而产生的数值叫 <Term id="hidden-state"/>，也常称激活。它与固定参数不同：参数是运算读取的配置，中间表示是本次输入通过运算后产生的数据。`XW` 中，`W` 是参数，而结果 `Y` 是这次计算产生的表示。

从输入沿着这些步骤算到输出，叫一次 <Term id="forward"/>。基本生成循环会反复调用前向计算。后面加入缓存后，每一轮送入模型的数值范围会变化，但“先计算表示，再决定下一个 token”的依赖还在。

<span id="training"></span>
## 训练改变权重，推理使用权重

<Term id="training"/> 时，模型把自己的输出与训练目标比较，再按学习算法调整参数。真实嵌入表和转换矩阵中的数值，是这样逐步得到的。本章的数值直接由我们填写，所以不应期待它们已经“知道北京是首都”。

推理时，一般读取训练完成的参数，根据当前输入计算结果。对话变长会改变输入和中间表示，却不会让模型参数自动吸收这段对话。以后讨论“Agent 记忆”时，必须分清写入上下文、保存外部记录与更新模型参数这三种行为。

回到熟悉的后端视角，可以做一个有限的对照：模型权重像服务加载的一份固定数值配置，输入 ID 像这次请求的输入，中间表示像处理过程中产生的临时数据。这个比喻有助于区分生命周期，但并不意味着模型是规则配置系统。

## 用一个变化检查自己的理解

把第一项“北京”的向量从 `[1,0]` 临时改成 `[3,0]`，保持其他输入行和 `W` 不变。刚才逐行矩阵乘法的哪些输出会改变？

<details>
<summary>展开答案与下一章的动机</summary>


只有第一行从 `[2,0]` 变成 `[6,0]`；其他行不变，因为每一行独立与 W 相乘。这说明我们还没有实现上下文信息的交换。下一章将增加一项操作，让当前行可以读取其他行的内容；那时，前文变化就可能影响当前行的结果。


</details>
