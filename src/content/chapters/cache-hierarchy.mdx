上一章的引擎已经能在请求结束后释放 KV。现在来了第二个用户，输入仍然以同一段很长的系统说明开头。重新算这段说明没有改变数学结果，却又花了一次 Prefill 时间。我们想保留的，正是这一段已经计算好的历史 K/V。

先限定讨论对象：我们复用的是同一模型对**完全一致的 token 前缀**产生的中间结果。文本看起来相似、语义相同，都不够。模型看到的输入 ID、位置和参与计算的权重必须兼容。

## 两个请求能共享到哪里

把一个块暂定为 4 个 token。请求 A 是 `[0,1,2,3,4,5]`，请求 B 是 `[0,1,2,3,6]`。它们前四个位置相同，因此在同一权重、同一位置规则和同一执行配置下，前四个位置每层的 K/V 可以共用。A 的后两个位置和 B 的最后一个位置分开存。

如果 B 改成 `[0,1,7,3,6]`，不能因为第四个 ID 又相同，就继续共用第四个位置。这个位置的表示已经通过前面的层利用了第三个位置；它的 K/V 也可能变化。缓存键必须描述完整的前缀依赖，而不只是当前块里有哪些 token。

<Term id="prefix-cache" context="这里复用的是不同请求之间相同前缀的 K/V，省掉这段输入的重复计算。" /> 与单请求内部的 KV Cache 解决两个层次的问题。后者让同一回答的连续生成不重算历史；前者让后来的请求也能受益。两者都会占用容量，但拥有者和释放时机不同。

vLLM 的自动前缀缓存使用块及其前缀身份来组织复用；实际缓存键还需要考虑 LoRA、多模态输入等附加身份。具体键的实现应查对应版本，不能在业务层只拿原始字符串做一个哈希就替代引擎检查。[官方设计](https://docs.vllm.ai/en/latest/design/prefix_caching/)

## 命中后还要做什么

命中 1,000 个前缀 token，不代表服务可以直接返回答案。新问题仍要计算；新生成位置仍要计算 Q/K/V、读取历史 K/V、执行其他层并采样。Prefix Cache 主要减少重复 Prefill，不会消除长历史对 Decode 的读取成本。

还要区分“存在缓存”与“能立即使用”。块可能已经被其他活动请求引用；也可能在 GPU 池里可直接寻址；也可能被移到 CPU 内存或远端。调度器必须把缓存可用性、计算预算和本轮 KV 容量一起考虑。

<details>
<summary>为什么不是直接缓存完整回答？</summary>

完整回答缓存绕过模型执行，适用于允许返回同一结果的业务；KV 缓存保存的是计算中间状态，后面仍然可以输入不同问题或进行不同采样。二者的失效规则、安全边界和命中条件不同。不能用“都是缓存”推导出同一种产品行为。

## 搬回来，还是重新算

假设一段可复用 KV 有 200 MiB，从较慢层搬回 GPU 的有效速度是 10 GiB/s。只算数据传输，时间是 200 / 1024 / 10 秒，约 19.5 ms。若还需 5 ms 查找、排队和元数据处理，加载成本约 24.5 ms。重算这段前缀若需要 15 ms，搬运反而不划算；若重算需要 100 ms，缓存才可能明显节省时间。

这些数值是教学设定。实际有效带宽必须从端到端路径测量：CPU 分配、PCIe、网络、存储和 GPU 等待都可能参与其中。压缩还会增加编解码成本。

## Agent 会话为什么让问题更明显

一个 Agent 可能先读取说明，生成工具调用，等待工具数秒，再把工具结果接回上下文。等待期间 GPU 并不计算这个请求，但如果所有会话都长时间保留 KV，显存会被不活跃的上下文占据。

因此，会话状态要分清三类：业务对话记录、可重建的模型 KV、正在运行的请求。业务记录可以长久保存；KV 可以被淘汰后重算；活动请求需要超时和取消处理。不要把“保留聊天历史”实现成“永不释放 GPU 块”。

工具返回顺序、消息模板、隐藏的系统提示和 tokenizer 版本，也会改变实际 token 前缀。先记录规范化后的 ID 与长度，再解释命中率。跨租户共享还要考虑信息暴露和计时侧信道；本课程的默认工程实验只在同一可信租户内比较，避免让缓存身份变成隐式共享接口。

## 如何证明策略有用

构造两组相同请求分布：一组明确禁用前缀缓存，一组启用；固定模型、输入长度、输出上限和到达模式。分别测冷启动、预热后和容量压力下的结果。至少记录 TTFT、输出 token 间隔、吞吐、缓存命中 token 数、被淘汰与重算数量。

如果只反复发送一个完全相同的提示词，你证明的是这个极端场景能命中，尚未证明生产会话能受益。迁移练习是把共同前缀从 80% 降到 10%，解释结果为什么变化；再在前缀中间插入一个 token，预测可复用边界。

容量还可以通过降低每个数的存储成本来改善。下一章讨论量化，但必须同时把质量纳入验收。
